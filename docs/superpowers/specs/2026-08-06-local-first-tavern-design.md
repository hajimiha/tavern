# 《雾灯谷纪事》本地优先酒馆化设计

## 1. 目标与边界

本阶段把现有像素经营游戏升级为完整的酒馆式叙事前端，但不连接任何 LLM，不读取、创建或保存 API 密钥，也不发出模型请求。项目继续保持纯前端。

本阶段交付两层能力：

1. 建立稳定的 API 适配接口和禁用实现，为未来接入模型预留清晰边界。
2. 完成可独立运行的世界书、预设、角色卡、会话、变量、分支和本地剧情 UI。

地图拖拽与“金币”替换已在本轮前序任务完成，继续作为最终回归测试范围。

## 2. 技能与方案来源

- 已安装 `ariespo/tavernlike` 到 `C:/Users/qixin/.codex/skills/tavernlike`。
- 采用其 v3 React 结构：Dexie 持久化、世界书匹配、提示顺序、六标签解析、楼层变量快照、多会话与编辑器纯函数。
- 采用 `/sillytavern-web` 默认：游戏模式、`maintext/option/sum/vars/thinking/think` 六标签、单适配器、非 schema-first。
- 不照搬模板的白底内联样式、emoji、浏览器 `alert/confirm/prompt` 或真实 API 路由；这些部分必须适配现有深苔绿/铜金像素系统和应用内反馈。

## 3. 推荐架构

### 3.1 本地优先 API 适配层

定义 `TavernApiAdapter`：

```ts
interface TavernApiAdapter {
  readonly mode: 'disabled' | 'remote'
  readonly label: string
  prepare(request: TavernRequest): TavernPreparedRequest
  stream(request: TavernPreparedRequest, signal?: AbortSignal): AsyncIterable<TavernStreamEvent>
}
```

本阶段只提供 `DisabledTavernApiAdapter`。`prepare` 可以生成可检查的请求预览，`stream` 返回类型化的 `TAVERN_API_DISABLED` 错误，绝不调用 `fetch`。生产 UI 不提供可触发网络请求的路径。

`AppSettings.api` 保留未来兼容字段，但默认 `enabled=false`、URL/模型为空。连接页显示接口契约、请求预览和“模型未接入”；密钥输入禁用且不持久化。

### 3.2 本地叙事路径

NPC 会话使用现有 `mockDialogueProvider`，升级为六标签事件源：

- `maintext`：剧情正文。
- `option`：2–4 个可点击行动。
- `sum`：本楼层摘要。
- `vars`：会话变量深合并。
- `thinking/think`：只用于折叠式调试展示，默认不展开。

本地回复同样经过流解析器和变量快照流程，因此未来换成远程适配器时 UI、数据库和历史分支无需改写。

## 4. 数据模型

Dexie 保存：

- `Lorebook`：条目、关键词、次关键词、位置、优先级、概率、递归规则。
- `ChatPreset`：提示文本、自定义 prompts、prompt order、未来采样参数。
- `CharacterCard`：15 名 NPC 的人物设定、性格、场景、首句、示例对白、绑定世界书及关系阶段。
- `ChatSession`：NPC、多楼层消息、变量、摘要、分支来源、创建/更新时间。
- `AppSettings`：游戏模式、标签集、激活世界书/预设、API 禁用状态。

首次启动只在对应表为空时写入：雾灯谷公共世界书、地点世界书、暮色叙事预设和 15 张 NPC 角色卡。用户上传的关系阶段立绘仍由现有上传结构保存，不被默认数据覆盖。

## 5. 界面结构

### 5.1 NPC 酒馆会话

现有 `DialogueView` 变为沉浸式酒馆对话：

- 顶栏：NPC、好感阶段、本地叙事状态、当前会话。
- 正文舞台：最后一楼的剧情正文和流式光标。
- 行动区：结构化选项与自由输入。
- 记忆侧栏：共同记忆、命中世界书、会话变量、楼层摘要。
- 历史抽屉：跳转、编辑、删后续、从此分支。

聊天依旧遵守原游戏精力规则；世界书和会话只负责叙事记忆，不直接改写经营 reducer。

### 5.2 酒馆中枢

设置按钮打开 `TavernHubModal`，提供六个标签：

1. 接口：禁用适配器状态、契约说明、请求预览、未来连接字段。
2. 世界书：启停、导入/导出、新建、重命名、条目编辑。
3. 预设：提示文本、自定义 prompts、顺序和参数编辑。
4. 角色卡：15 名 NPC 卡片、首句、示例对白、绑定世界书和关系阶段信息。
5. 会话：创建、加载、重命名、分支、删除、更新时间。
6. 变量：游戏状态只读镜像、会话变量编辑、楼层变量快照。

所有删除、覆盖和放弃修改操作使用应用内确认层。导入错误在面板内显示，不调用浏览器原生警告框。

## 6. 视觉与交互

- 沿用深苔绿、夜蓝黑、铜金、羊皮纸和紫雾变量色，不采用模板白底后台样式。
- 世界书表现为黄铜索引柜；角色卡表现为像素档案；会话分支表现为丝线谱系；接口页表现为未点燃的符文终端。
- 使用 Phosphor SVG 图标，禁止 emoji。
- 标签、图标按钮和主要操作最小 44px；有可见焦点和中文 `aria-label`。
- 375px 下标签横向滚动、内容单列；桌面使用左导航、中工作区、右摘要的高密度 Bento 布局。
- 所有动效支持 `prefers-reduced-motion`；管理中枢按需懒加载。

## 7. 错误与安全

- API：任何发送尝试均被禁用适配器拦截并显示应用内说明；无网络调用。
- IndexedDB：初始化失败时退化为当前页面内存存储并提示无法跨刷新保存。
- 导入：先完整校验再事务写入；部分失败列出文件名和原因。
- 删除：应用内二次确认；唯一默认预设和公共世界书不可被无替代项删除。
- 密钥：本阶段没有可编辑密钥字段、没有环境变量读取、没有导出密钥数据。

## 8. 测试与验收

- API 合同测试：禁用适配器不触发 `fetch`，请求预览可生成，发送返回类型化禁用错误。
- 核心测试：世界书匹配、提示顺序、跨 chunk 标签、变量深合并、导入导出、编辑器纯函数。
- 默认数据测试：15 张角色卡、两册世界书、默认预设、API 禁用。
- 组件测试：酒馆中枢六标签、应用内确认、NPC 本地楼层、选项发送、历史分支、变量快照。
- 回归：地图拖拽、金币文案、全量 Vitest、TypeScript、Vite 构建。
- 视觉：1440×900、1024×768、768×1024、375×812 无溢出、无控制台错误、模态完整可用。
