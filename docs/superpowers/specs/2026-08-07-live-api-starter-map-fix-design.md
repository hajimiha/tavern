# 新手开局、真实模型 API 与地图出行修复设计

## 目标

本轮把当前“演示存档 + 本地假对话 + 偶发无法点击地图建筑”的原型，收束为一个可信的新游戏入口：玩家从第 1 天抵达雾灯谷，只持有少量金币与种子；在酒馆控制台配置 DeepSeek 或兼容 OpenAI Chat Completions 的服务后，NPC 对话由真实模型生成；任何一次地图拖动结束后，下一次主动点击建筑都能稳定打开行程预览。

## 范围与边界

- 仍然是纯前端原型，不新增应用服务器、代理服务或云端数据库。
- 浏览器直接请求玩家填写的 API 地址，因此界面必须明确提示 CORS 与密钥暴露风险。
- API 密钥默认只放在 `sessionStorage` 和 React 内存中；只有玩家主动开启“记住密钥”时才保存到本机 IndexedDB。
- 不把任何真实密钥写入源码、测试快照、请求预览、日志、提交记录或 GitHub。
- DeepSeek 是开箱即用的预设；自定义模式支持任何采用 Bearer 鉴权与 `/chat/completions`、`/models` 路径的兼容服务。
- 未启用或未配置 API 时保留本地叙事作为可见的离线模式；启用 API 后，请求失败必须显示具体错误，不静默伪装成本地模型回答。

## 新手数据

初始状态调整为第 1 天春季清晨：农场、5/5 精力、500 金币、五项技能均为 1 级且经验为 0，基础生命、攻击、魔力与魔法伤害恢复为新手数值。背包仅含 8 包月铃萝卜种子与 4 包雾荚豆种子；24 块田全部为空，NPC 好感与共同记忆全部清零，委托全部处于可领取状态，法术尚未学习，矿洞仅开放第 1 层且没有电梯记录。

这里保留初始工具各 1 级，因为锄头、鱼竿和镐在现有数据结构中属于不可丢弃的能力状态，不属于可出售背包物品；这样不会破坏耕种、钓鱼和挖矿入口。

## API 配置模型

`TavernSettings` 增加一个公开的 `api` 配置对象：

```ts
interface TavernApiConfig {
  provider: 'deepseek' | 'openai-compatible'
  baseUrl: string
  model: string
  temperature: number
  maxTokens: number
  rememberKey: boolean
  persistedApiKey?: string
}
```

`adapterMode` 扩展为 `local | remote`。默认是 `local`，避免没有密钥的新玩家误以为已经联网。DeepSeek 预设使用 `https://api.deepseek.com` 和当前公开模型 `deepseek-v4-flash`；自定义模式允许修改地址与模型名。仓储读取旧设置时用默认值深度合并，保证现有 IndexedDB 数据不会因缺少新字段而报错。

密钥管理由独立模块负责：会话密钥使用固定的 `sessionStorage` 键；开启本机记忆时才把值放进设置对象；关闭记忆或清空密钥时同步清除持久化副本。UI 只展示掩码或是否已配置，永不回显到请求预览。

## 模型请求与响应

远程适配器实现两个动作：

1. `testConnection` 请求 `${baseUrl}/models`，验证鉴权并返回模型列表。
2. `stream` 请求 `${baseUrl}/chat/completions`，设置 `stream: true`，逐行解析 `text/event-stream` 中的 `data:` 数据；遇到 `[DONE]` 结束。若兼容服务返回普通 JSON，也读取 `choices[0].message.content`。

接口错误统一转为中文可执行提示，区分地址无效、缺少密钥、401/403 鉴权、429 限流、CORS/网络失败、响应格式异常和用户主动中止。

远程剧情引擎复用既有角色卡、世界书扫描、预设、历史消息、游戏变量和六标签解析器。模型被要求输出：

```text
<maintext>NPC 的本回合正文</maintext>
<option>下一步行动，每行一项</option>
<sum>本回合摘要</sum>
<vars>{}</vars>
```

若模型没有完整标签，正文回退到原始输出，选项回退到角色默认选项，避免界面出现空白。模型返回的变量补丁继续经过既有 `applyParsedToChat` 处理，并随会话写入 IndexedDB。

## 对话体验

对话组件统一调用 `sendTurn`。状态条显示“本地叙事”或“DeepSeek · 模型名”；远程生成时显示模型请求状态，输入区注明消息会发送到玩家配置的服务。网络错误使用现有酒馆内联警告，不调用浏览器 `alert`。停止按钮继续通过 `AbortController` 中断流式请求。

## API 控制台体验

API 页采用与现有像素酒馆一致的暗色高密度 Bento 布局：连接状态卡、提供方与端点、密钥与模型、生成参数、安全说明和操作区。所有输入与按钮具有唯一描述性 ID；密码输入提供显隐按钮；地址和模型在失焦时做内联校验；测试与保存有独立加载态、成功态和失败态。交互按钮最小高度 44px，动画遵循 `prefers-reduced-motion`。

## 地图交互修复

根因是 `suppressHotspotClickRef` 在拖动结束后一直保持 `true`，如果浏览器没有立刻产生一次 click，它会误吞下一次真正的建筑点击。修复方式是只在同一指针手势的同步 click 周期内抑制点击，并用零延迟计时器自动解除；组件卸载时清理计时器。

右下角六宫格不再承担必要功能：拖动、触控和方向键已经负责平移。因此移除四个方向按钮，保留两个紧凑图标按钮——“定位当前地点”和“重置视野”。手机端仍有地点列表作为无精确点击能力时的可访问后备入口。

## 验收标准

- 初始界面显示第 1 天、500 金币、5 点精力，背包只有两类种子，农田全部为空。
- API 控制台能保存公开配置、会话保存密钥、可选本机记忆密钥、测试 `/models`，并能显示中文状态。
- 模拟 SSE 与普通 JSON 的单元测试都能得到模型正文；401、429、网络错误与中止都有可预测结果。
- 在启用 API 的配置下，NPC 发送消息走远程适配器并将模型文本写入会话；未启用时明确走本地叙事。
- 地图拖动产生的紧随 click 被抑制，但计时器解除后下一次主动点击建筑会打开“前往该地点”的行程预览，确认后更新当前位置。
- 四个方向按钮不再渲染；定位和重置仍可用；键盘方向键、Home、C 与移动端拖动仍可用。
- 全量测试和生产构建通过，并在桌面与窄屏尺寸做视觉检查。
