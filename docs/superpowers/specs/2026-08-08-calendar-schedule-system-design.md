# 雾灯谷日历、人物行程与消磨时间系统设计

## 目标

为现有前端游戏增加一套真正驱动玩法与酒馆叙事的时间生态：一年固定 365 天，日期跨年、季节和星期可靠轮转；十五位 NPC 拥有生日与分时行程；节日能够改变参与者所在地并为模型提供活动规则；玩家可以精确前往某个时刻或消磨若干天、小时和分钟。

本轮仍为纯前端实现，不增加后端服务。时间、日历和行程随现有游戏存档持久化；世界书内容继续使用当前 Dexie 与仓库默认内容机制。

## 方案选择

采用“中央日历引擎 + 数据驱动日程 + 统一岁时手册”。日期换算、时间推进、NPC 所在地、生日和节日判断都由无副作用的领域函数提供，游戏场景、日历 UI、存档和酒馆变量共同调用。

未采用以下两种方案：

- 在各个页面分别硬编码 NPC 地点：实现较快，但跨日、节日和模型上下文容易互相矛盾。
- 本轮同时制作完整的玩家日程编辑器：灵活度高，但会显著扩大数据校验、跨设备内容发布和移动端编辑范围，偏离当前玩法目标。

## 日历规则

- 一年固定 365 天，不设置闰年。
- 使用十二个月及公历月长：31、28、31、30、31、30、31、31、30、31、30、31。
- `year` 从 1 开始；现有 `day` 统一解释为当年的第 1 至 365 天。
- 星期以第一年第一天为周一连续轮转。
- 雾灯谷以春季开年以兼容现有新手种子：1 至 3 月为春，4 至 6 月为夏，7 至 9 月为秋，10 至 12 月为冬。
- `minutes` 始终保持在 0 至 1439。旅行、消磨时间和战败复苏都走同一时间推进函数，不再出现分钟超过一天但日期未变化的状态。
- 每跨过一个自然日，恢复每日精力，重置医院、聊天和赠礼的每日限制；作物按真实经过分钟成长。跨越多天时只计算一次结果，不逐分钟循环。

## NPC 行程

每位 NPC 具有：

- 固定生日；
- 基础日程，覆盖一天全部时间；
- 一项具有个人特征的每周休闲变体；
- 节日参与覆盖。

行程段以开始分钟、结束分钟、地点和活动说明表示。通常包含清晨、工作、休闲、夜间四段。例如柳安白天在杂货店经营，傍晚前往图书馆核对商路旧账；芙蕾雅部分午后会去森林或医院照料草药；汐野会在清晨码头、午后图书馆和傍晚渔家之间移动。

当前地点人物列表、地点札记和 NPC 立绘只显示此刻实际在场的人物。节日期间，参与者在活动时段移动到会场。角色生日当天，人物档案和日历显著标记，偏爱礼物的好感收益翻倍。

## 节日

全年设置十二个节日，每月一个，活动主题不重复：迎岁灯会、潮信祭、播种祭、林铃花会、风筝讯使节、长昼渔火祭、星河许愿夜、月穗丰收会、羽火锻造祭、薄雾巡游、回声矿灯祭和守夜落雪宴。

每个节日数据包含日期、会场、起止时间、参与 NPC、简介以及三项具体活动。节日活动通过以下方式落地：

- 月历与日期详情显示活动时间、会场和项目；
- 活动时段改变参与 NPC 的位置；
- 当前节日名称进入酒馆变量，使对应世界书条目自动命中；
- 日期详情提供前往会场的入口，沿用既有地图旅行与时间消耗逻辑。

## 世界书与模型上下文

新增默认世界书“雾灯谷·岁时与庆典”，包含：

- 365 天、跨年、星期、季节和营业时间规则；
- 生日及生日赠礼规则；
- 十二个节日的会场、时段、参与者和活动详情。

人物档案世界书为十五位 NPC 增加生日和代表性行程摘要。酒馆每次对话传入年份、日期、星期、季节、时间、天气、当前节日、NPC 当前地点和当前活动。提示词装配器把变量内容纳入世界书扫描，因此当天节日条目无需玩家先说出节日名称也能命中。

## 界面设计

HUD 的时间区改为可点击入口，使用 Phosphor 日历图标与明确的悬停、聚焦反馈。点击后打开“岁时手册”，包含三个标签：

1. **月历**：显示月份网格、今天、选中日期、生日和节日标记；右侧为选中日详情和近期事件。
2. **人物行程**：角色筛选器与纵向时间轴，突出当前时段、当前所在地和下一段安排。
3. **消磨时间**：提供“前往指定时刻”和“经过一段时长”两种模式，显示目标日期预览与跨日影响后再确认。

桌面端使用月历与详情双栏；手机端变为单列卡片流，月份网格保持七列但缩减装饰文字，所有触摸目标至少 44 像素。复杂表单使用可见标签、就地错误和确认摘要，不调用浏览器原生警告框。微动效只使用透明度与位移，并尊重 `prefers-reduced-motion`。

## 状态与存档

`GameState` 新增 `year`。旧存档缺少该字段时迁移为第一年；异常年份、日序和分钟安全回退或钳制。当前模态类型新增 `calendar`。时间推进是单一 reducer 动作，目标模式先在 UI 换算为正的经过分钟，reducer 再统一应用。

自动存档会保存推进后的年、日和时间。导入旧存档、新建游戏和刷新恢复都使用相同净化规则。

## 通知与错误处理

- 目标时刻等于当前时刻时阻止提交并显示就地说明。
- 目标时刻早于当前时刻时明确预览为次日。
- 时长必须大于零，单次最多 365 天。
- 战斗进行中不允许消磨时间。
- 时间推进成功只产生一条摘要通知，避免按跨越天数制造通知堆叠。
- 通知区域限制可见数量并自动退出，重复内容不会无限堆积。

## 测试与验收

- 领域测试：日期换算、月长、跨年、星期、季节、精确目标时间、跨多日重置。
- 行程测试：工作日、每周变体、节日覆盖、午夜边界、生日判断。
- reducer 测试：旅行跨日、消磨时间、作物成长、每日状态恢复、生日赠礼。
- 世界书测试：节日条目完整、角色生日与行程写入、当前节日能被提示词装配命中。
- 组件测试：HUD 入口、月历标记、角色时间轴、两种时间表单、错误状态和会场旅行。
- 浏览器验收：1440 像素桌面与 390 像素手机，验证无横向溢出、可滚动、键盘可达、无重复 ID，并在刷新后保留日期与时间。
