# 《雾灯谷纪事》纯前端原型设计规格

## 1. 产品定位

《雾灯谷纪事》是一款以 LLM 角色互动为叙事核心、以农场经营和村庄生活为日常循环、以矿洞战斗与五行魔法为中期成长线的 Web 游戏原型。当前交付只包含前端：所有数值、NPC 回复、任务变化、战斗和时间推进均使用本地模拟状态，不包含数据库、账号、真实模型调用或任何后端接口。

主要体验目标：

- 第一眼就是完整的精细像素世界，而非管理后台式卡片集合。
- 玩家在一个主页面内始终知道“我在哪里、现在几点、还剩多少精力、下一步能做什么”。
- 所有用户要求的系统都有可打开、可切换、可看到具体内容的界面，不使用空白占位模态框。
- LLM 对话界面像游戏叙事系统，而不是嵌入一个通用聊天机器人。
- NPC 立绘资源与界面解耦，未来按 NPC 与好感阶段上传图片即可替换。

## 2. 方案比较与选择

### 方案 A：React 舞台式单页原型（采用）

使用 React、TypeScript、Vite 和本地 reducer 构建单页游戏舞台。中央场景、HUD、地图和模态系统共享一个可预测的游戏状态；像素地图为真实位图，交互热点使用语义按钮覆盖。

优势：适合密集交互与状态联动；无需后端即可演示完整循环；未来接入 LLM 或存档服务时边界清晰；性能和自动化测试成本可控。

### 方案 B：纯 HTML/CSS 多页面原型

初始体积小，但跨地点状态、模态组合、战斗和对话流很快变得难以维护，也不利于未来接入模型流式响应。仅适合静态视觉稿，因此不采用。

### 方案 C：Canvas 全画布游戏界面

视觉自由度最高，但中文排版、键盘导航、模态内容、表单与测试成本明显增大；对当前“复杂 Web 前端框架”的目标不利，因此只把像素世界做成位图资产，不把整套 UI 放进 Canvas。

## 3. 视觉系统

### 3.1 主题

视觉主题为“暮色乡野 × 隐秘魔法”。世界处于秋末初冬的金色傍晚，农田、木屋和灯火呈现温暖经营感；远处矿山、魔女之家和魔物娘商店带有靛蓝、紫铜和萤光矿物色，形成独特的奇幻悬念。

界面不是复古低清复制，而是“像素材质 + 现代信息层级”：

- 场景、地图、地块与环境纹理使用精细像素画。
- HUD 使用清晰中文字体、像素切角、双层描边和铜制细节。
- 模态框使用深色半透明木漆/夜蓝表面，不使用廉价玻璃拟态。
- 强调色只用于当前目标、可执行操作和稀有状态，避免全屏高饱和。

### 3.2 颜色令牌

- 背景夜蓝黑 `#0E1717`
- 深苔绿 `#183128`
- 场景苔绿 `#31523C`
- 羊皮纸米色 `#F2E5C6`
- 次级文字砂金 `#CDBB91`
- 铜金主操作 `#D5A64A`
- 成熟/成功绿 `#86B86D`
- 魔法紫 `#9A7AC7`
- 浆果危险红 `#C95D5D`
- 水元素蓝 `#5FA8BC`

颜色不单独承担含义；成熟、受伤、克制、不可用等状态同时配合图标、文字或纹理。

### 3.3 字体与图标

中文正文使用现代无衬线字体栈，标题使用具有手作结构感的中文黑体/圆体栈；数值启用等宽数字以避免时间和金钱跳动。像素字体只用于极短英文副标题和装饰编号，不用于大段中文。

通用图标使用 Phosphor 的统一线性/双色风格；技能、五行和游戏道具使用同一笔画语言的内联 SVG。全站禁止 emoji。

### 3.4 动效

- 交互反馈在 80–120ms 内出现；常规模态进入 220ms，退出 160ms。
- 地图当前地点有缓慢呼吸轮廓；作物成熟产生一次柔和光扫。
- 点击地块后详情卡从地块方向缩放进入，保持空间连续性。
- 金钱、精力和好感变化使用短促的数字浮动及颜色脉冲。
- LLM 回复逐行显现并提供“立即显示全部”，不锁住输入。
- 每个视图最多同时运行 1–2 类明显动画，全部支持 `prefers-reduced-motion`。

## 4. 主页面信息架构

### 4.1 顶部 HUD

顶部 HUD 固定但不遮挡内容，包含：

- 当前地点与副标题，例如“苔灯农场 · 南坡田区”。
- 第 6 日、秋季、周三、17:40、天气“薄雾转晴”。
- 精力 4/5，显示下一次操作代价预告。
- 金钱 2,480 金叶。
- 五项技能：钓鱼 2、农耕 4、挖矿 3、战斗 2、魔法 3。
- 派生数值入口：生命 28、物攻 7、魔力 18、魔伤 9。
- 背包、任务、角色和系统设置按钮。

桌面端技能以紧凑徽记呈现；小屏只显示核心数值，其余收进“角色”抽屉。

### 4.2 中央像素舞台

中央区域占据主视觉，随地点切换：

- 农场：像素背景之上显示 4×6 可交互农田。每格展示作物、阶段、剩余成熟时间、浇水状态和异常状态。点击后打开地块详情，可执行浇水、施肥、收获、铲除；操作前明确显示精力与道具成本。
- 其他地点：显示地点像素背景、建筑内景和 1–3 个 NPC 立绘框。原型不绘制人物本体，立绘框以人物名牌、职业纹章、好感状态和高级剪影蒙版构成。未来资源通过 `portraitByAffinity` 映射替换。
- 场景内提供今日可做事项、开放时间、NPC 在场状态和特殊事件提示。

### 4.3 左侧叙事栏

左侧为可折叠“今日线索”：主线进度、当前追踪委托、作物即将成熟、医院今日次数等。它只展示最多三条高价值信息，完整内容进入任务手册。

### 4.4 右侧上下文栏

右侧显示当前地点详情与操作预告。农场时显示地块统计和今日建议；其他地点显示 NPC 名单、关系阶段、今日已经互动的类型和地点功能。它也是小屏底部抽屉的数据源。

### 4.5 底部村庄地图

底部不是地点卡片网格，而是一张完整的横向像素地图：河流、道路、农田、村落、矿山、森林和海岸在同一透视中连续绘制。10 个地点通过透明语义按钮热区覆盖；悬停/聚焦时只描出建筑轮廓和路牌，不破坏画面。

地图支持：

- 当前地点高亮、目标任务标记、开放/关闭状态、NPC 活动提示。
- 点击地点显示行程浮层：路程、到达时间、营业状态、在场人物、可能消耗；二次确认后切换场景。
- 键盘和移动端提供等价的地点列表抽屉，避免依赖精确点击。

## 5. NPC 与 LLM 互动

全村固定 15 名女性 NPC：

- 村长家：村长洛岚、草药师芙蕾雅、女儿弥奈。
- 商店：店主柳安、账房桃弥。
- 铁匠铺：铁匠岩雀。
- 魔物娘商店：店主塞拉、育种师米菈、饲育员绮萝。
- 魔女之家：魔女黛芙。
- 猎人帐篷：猎人凛。
- 渔家：船主潮音、钓师汐野。
- 医院：医师维娜、护理师苏槿。

点击 NPC 立绘框打开关系面板，包含好感心级、关系称谓、今日互动记录、偏好线索和五个操作：交谈、赠礼、交易、提交任务、查看档案。无对应功能时按钮仍可见但禁用，并解释原因。

好感阶段分为陌生、熟识、信赖、亲密、羁绊五级，每级映射独立立绘地址与问候文案。送礼和任务可以跨级触发关系事件；当天重复聊天不会重复加好感。

LLM 对话以“灵犀对话”呈现：

- 上方显示 NPC 当前情绪、关系阶段、地点与正在讨论的话题。
- 对话消息为游戏气泡，不暴露 system prompt、token 或模型名。
- 输入区提供三条情境化建议，也允许自由输入中文。
- 回复期间显示轻量流式状态，可停止或立即显示全文。
- 关系记忆用玩家可理解的“她记得”标签展示，如“雨夜借伞”“偏爱月铃花”。
- 原型使用预置回复序列和定时字符显现；未来通过单一 `DialogueProvider` 接口替换为真实 LLM。
- 失败时在对话窗内部显示“思绪被雾气打断”，提供重试与使用本地回应，不调用浏览器 alert。

## 6. 地点与功能界面

### 6.1 村长家

显示壁炉大厅与公告墙。任务板模态框包含普通委托、限时委托、关系委托三个标签；每项显示发布人、剩余时间、所需物品、报酬、村长好感和发布者好感。完成按钮会检查本地背包并给出内部确认/错误提示。

### 6.2 商店

交易模态框含“购买”和“出售”两页。商品有像素道具图标、名称、说明、持有数、单价和数量步进器；种子显示季节与成熟日数。结算栏实时显示总价与余额变化。

### 6.3 铁匠铺

提供工具升级、矿石精炼和装备修理。原型展示铜制锄、潮汐钓竿与矿镐的升级树，以及所需材料不足的完整禁用态。

### 6.4 魔物娘商店

先展示“林下共生牧场”购买合同；未拥有牧场时，魔物娘与饲料页可浏览但不可购买。购买后可选择：史莱姆娘（产出凝胶）、蜂娘（提升蜂蜜收益）、岩羊娘（提高矿石副产物）、蘑菇娘（夜间产出菌菇）。界面强调经营伙伴与能力，不做露骨表现。

### 6.5 魔女之家

药剂商店包含永久提升类、恢复类、战斗投掷类。永久药剂明确展示当前上限、提升值、价格和限购条件；战斗药水标注五行属性及克制对象。

### 6.6 猎人帐篷

训练面板包含基础体能、武器架势、怪物研究。训练消耗 1 精力，增加战斗经验；显示本次收益、等级进度和今日训练记录。

### 6.7 矿洞

矿洞界面包含层数选择、电梯节点、矿点与怪物预览。每五层为安全电梯层，无怪物但可以挖矿；已解锁电梯层可以直接抵达。进入新层消耗 1 精力。

遭遇怪物后进入回合制战斗模态框：玩家和敌人状态、行动顺序、物理攻击、五行法术、道具、防御、逃跑。五行规则固定为金克木、木克土、土克水、水克火、火克金；克制时显示文字与环形五行提示。失败打开“翌日苏醒”结算，时间推进至第二天并恢复基础状态。

### 6.8 渔家

商店页出售鱼竿与鱼饵；钓鱼页展示水域、鱼影、饵料选择和抛竿按钮。一次钓鱼消耗 1 精力，随后运行简化节奏条小游戏；原型可得到“银鳞鲫”并更新背包与钓鱼经验。

### 6.9 图书馆

法术书架按金木水火土分类，展示等级要求、魔力成本、伤害/恢复效果和已学状态。仅可学习不高于当前魔法等级的法术，学习消耗 1 精力。

### 6.10 医院

恢复 2 精力，支付 180 金叶，每天限一次。治疗前确认变化，已使用后显示当日医生建议和次日重置时间。

## 7. 补充系统

- 背包：道具按作物、材料、礼物、战斗、任务筛选；重要任务物品不可误卖。
- 角色面板：技能等级、经验、收益加成、生命/魔力派生值、五行法术图谱。
- 任务手册：主线、村民委托、关系事件、已完成；可切换追踪目标。
- 日终结算：睡觉或战败后展示收入、经验、好感变化、作物成长和次日天气。
- 时间与营业：移动和部分操作推进时间；营业状态在地图和地点面板同时可见。
- 天气与季节：原型内包含薄雾、晴、雨三种天气状态，影响钓鱼提示和农田浇水状态。
- 设置：音量视觉控件、动效强度、文字速度、地图标签和高对比模式；原型不实际播放音频。
- 本地演示存档：使用内存状态；可提供“重置演示进度”，需二次确认。若使用 localStorage，仅作为可选前端演示能力，不伪装为服务端存档。

## 8. 状态与数据流

顶层 `GameState` 包含时间、天气、地点、精力、金钱、技能、背包、农田、NPC 关系、任务、矿洞、电梯、医院次数、牧场所有权和当前模态。所有用户操作通过命名清晰的 action 进入 reducer，例如 `TRAVEL_TO_LOCATION`、`WATER_PLOT`、`GIVE_GIFT`、`LEARN_SPELL`。

组件不直接修改共享状态。代价检查由纯函数完成并返回 `allowed`、`reason` 和 `previewDelta`，同一结果用于按钮禁用态、确认框和 reducer 校验，避免界面说可做但实际失败。

LLM 抽象为前端 `DialogueProvider`：原型实现返回预置分支和模拟流；未来实现可返回真实流式文本。界面层只消费标准事件，不依赖具体服务。

## 9. 错误、警告与通知

- 全部反馈在应用内完成，禁止 `alert`、`confirm`、`prompt`。
- Toast 用于非阻塞成功和轻量提醒，3–5 秒自动消失，支持手动关闭并使用 `aria-live="polite"`。
- 精力、金钱、材料不足等错误显示在对应操作附近，同时给出可恢复路径，例如“前往医院”或“出售作物”。
- 战败、铲除作物、重置进度等高影响操作使用明确确认模态框。
- 对话模拟超时、图片加载失败等提供可重试和降级内容，不留下空白区域。

## 10. 响应式与可访问性

桌面 1440px 为主展示尺寸，1024px 仍保持三栏舞台；768px 以下将左右栏合并为底部抽屉，地图变为可横向查看的全景区域并提供地点列表；375px 下保留所有核心操作而不产生页面级横向溢出。

所有交互元素拥有唯一、描述性 ID；按钮点击面积至少 44×44px；模态框支持 Escape 关闭、焦点锁定和关闭后焦点归还；Tab 顺序与视觉顺序一致；图片拥有中文替代文本；焦点环在像素风中表现为铜金双线框。

## 11. 性能策略

- 场景和地图输出 WebP/PNG 并声明固定尺寸，避免累计布局偏移。
- 首屏只预加载农场背景与地图；其他地点背景在用户首次接近/打开时惰性加载。
- 模态内容按功能动态导入；重复列表使用稳定 key，不进行无意义重渲染。
- 动画只使用 transform 和 opacity；地图热点不持续监听高频鼠标位置。
- 不引入重量级 UI 框架或通用动画库；核心动效使用 CSS。
- 字体优先使用高质量系统中文字体栈，避免阻塞首屏的外链字体。

## 12. 测试与验收

- 构建与类型检查必须通过。
- 关键状态单测：精力扣减、医院限次、任务提交、商店余额、魔法等级门槛、五行克制、电梯解锁和战败跨日。
- 组件交互测试：地图旅行、地块操作、NPC 五类互动、各地点模态打开/关闭、内部通知、键盘焦点回归。
- 自动检查所有交互 ID 唯一，页面不调用浏览器原生警告函数。
- 在 1440×900、1024×768、768×1024 和 375×812 截图检查；同时验证 reduced-motion。
- 最终逐项核对用户列出的所有地点、NPC 数量、技能与体力规则。

## 13. 规格自检

- 无待定功能或空白占位模块；NPC 立绘资源是明确的外部输入，并已有完整降级显示。
- 纯前端范围与未来 LLM 接口边界一致，没有暗含后端实现。
- 地图明确为连续像素画资产，地点热区仅负责交互，不以卡片网格替代地图。
- 所有精力消耗、每日限次、技能收益、矿洞电梯与五行克制规则均有唯一解释。
- 技术架构、交互层级、响应式策略与测试范围彼此一致。
